# 連線鎖法分析

以遊戲盤面輸入、三連提示及鎖法成功率為主的 GitHub Pages 靜態工具。

## 使用

- 最上方開始，順時針輸入 1–12，各出現一次；空白、逗號與全形數字皆可。
- 可選擇遊戲截圖，拖曳框選十二個數字，辨識後逐格確認，再套用到盤面。
- 點擊編號可鎖定，最多六個。成功率即時更新，無需按分析按鈕。
- 橙色代表可擴成值得保留六鎖的三連；可採用三鎖或六鎖。
- 動畫預設開啟，每段 150 毫秒。修改 `index.html` 的 `segmentDuration` 可調速度。
- 重洗、解鎖、動畫及素材統計縮成盤面下方一列。

## 面積模型及精確機率

所有被線段圍住的封閉區域都計入面積，以正十二邊形為 100%。這取代先前的 even-odd 模型。提供的遊戲截圖順序 `1 10 11 7 3 6 2 8 5 12 9 4` 在此模型下為 71.385%，與遊戲顯示的 71% 相符；even-odd 模型只有 42.080%。

完整枚舉 19,958,400 個鏡射代表，恢復鏡射後，固定 1 號在最上方有 35,130 個達到 90% 的排列；再恢復十二種旋轉，共 421,560 個。成功目錄記錄每種排列的面積，支援 90%–100% 的目標。條件機率為匹配所鎖位置的成功排列數除以 `(12 - 鎖定數)!`。

例如 90% 目標下，六個外框連號的成功率為 `81 / 720 = 11.25%`；只鎖相鄰三個連號則為 `2067 / 362880 ≈ 0.5696%`。前版 even-odd 模型的 30/720 不適用於目前的遊戲填色模型。

三連包含順時針或逆時針的連號及跨 12 → 1。保留線是同目標下六連基準成功數的三分之一；90% 的保留線為 27/720。此為明確的篩選標準，並非含尋找盤面成本的最佳素材策略。

## 圖片辨識

圖片像素僅在使用者的瀏覽器內處理。先以提供截圖的數字字型遮罩比對；不足時才下載 Tesseract.js 7.0.0 及英文模型，於本機辨識。圖片不傳送到辨識 API。其他字型、裁切不準、強烈光效可能造成錯讀，必須檢查結果；重複或缺少編號會被攔截。

## 檔案

- `index.html`：介面、封閉區域幾何、三連與條件機率、動畫、圖片辨識。
- `success-catalogue.js`：完整高面積排列目錄。
- `numeral-templates.js`：遊戲數字遮罩；不包含原截圖。
- `.nojekyll`：直接發布靜態檔案。

## 部署

GitHub Settings → Pages → Deploy from a branch → `main` → `/(root)`。
